# gh-actions-molecule-ansible

An Ansible role that installs and configures nginx, tested with
[Molecule](https://ansible.readthedocs.io/projects/molecule/) in a Docker
container. This repo is a hands-on project for practising Ansible testing and
CI/CD with GitHub Actions.

## What the role does

- Updates the apt cache and installs nginx from the Ubuntu repositories.
- Renders a custom index page from a Jinja2 template
  (`roles/nginx/templates/index.html.j2`) to `/var/www/html/index.html`, owned
  by `www-data` with mode `0644`.
- Restarts nginx through a handler whenever the package or the page changes.

## Repository layout

```
.
├── site.yml                    # playbook for the nginx role
├── deploy_docker.yml           # playbook for the nginx_docker role (AWS host)
└── roles/
    ├── nginx/
    │   ├── defaults/           # role defaults (none defined yet)
    │   ├── handlers/           # restart nginx
    │   ├── meta/               # role metadata
    │   ├── molecule/default/   # Molecule scenario: molecule.yml, converge.yml, verify.yml
    │   ├── tasks/              # install nginx, write the index page
    │   └── templates/          # index.html.j2
    └── nginx_docker/
        ├── tasks/              # create content dir, render page, run nginx container
        └── templates/          # index.html.j2
```

## The `nginx_docker` role

A second role, `roles/nginx_docker`, runs nginx as a Docker container instead of
installing it with apt. It is deployed to an AWS EC2 instance that is created by
a separate Terraform repository, `aws-gha-runner-terraform`.

- Creates `/opt/docker/nginx` and renders `index.html.j2` into it.
- Starts an `nginx:stable` container named `nginx` with
  `community.docker.docker_container`, publishing port 80 and mounting the
  rendered page read-only over `/usr/share/nginx/html/index.html`.
- Uses `restart_policy: unless-stopped`, so the container comes back after a
  reboot.

The role has no Molecule scenario yet; the Molecule tests and the CI workflow
cover only the `nginx` role.

### Deploying it

[`deploy_docker.yml`](deploy_docker.yml) applies the role to the `runner` host
group with `become: true`. The inventory file, `inventory.ini`, is generated by
the `aws-gha-runner-terraform` repository, which writes it into the root of this
repository when it creates the instance, so it holds that instance's address and is not written by hand. It is removed again
when you run `terraform destroy`, so it exists only while the instance is up.

Requirements on the target host: Docker and Python 3 installed, and the
`community.docker` Ansible collection on the control machine:

```bash
ansible-galaxy collection install community.docker

# run from the repository root, where inventory.ini is written
ansible-playbook -i inventory.ini deploy_docker.yml
```

Then open `http://<instance-public-ip>` to see the page. Port 80 must be allowed
in the instance's security group.

## Requirements

- Docker (running)
- Python 3 and a virtualenv
- Ansible, Molecule with the Docker driver, ansible-lint and yamllint

Developed with ansible-core 2.19 and Molecule 26.x, on Ubuntu 22.04 containers.

## Running the tests

Create and activate a virtualenv, install the tools, then run Molecule from the
role directory:

```bash
pip install ansible-core molecule "molecule-plugins[docker]" ansible-lint yamllint

cd roles/nginx
molecule test
```

`molecule test` runs the full sequence: create a container, apply the role
(converge), run it a second time and fail if anything changes (idempotence),
check that nginx serves the page (verify), and destroy the container.

Useful while developing:

| Command | What it does |
| --- | --- |
| `molecule converge` | Create the container and apply the role, leave it running |
| `molecule verify` | Run the checks against the running container |
| `molecule login` | Open a shell inside the test container |
| `molecule destroy` | Remove the container |

## CI

A GitHub Actions workflow (`.github/workflows/molecule.yml`) runs on every push
to `main`, on pull requests, and on manual dispatch. It sets up Python 3.13,
installs `requirements.txt`, lints with `yamllint` and `ansible-lint`, then runs
the Molecule sequence against `roles/nginx`: create, converge, idempotence,
verify and destroy.
